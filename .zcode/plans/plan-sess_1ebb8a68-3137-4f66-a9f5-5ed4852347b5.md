## Goal
Make alerts audible over music, prioritizing the looping safety warnings, with a consistent lift across all sounds, on BOTH tici/tizi and mici (tested on tizi). The mici constraint forces re-authored tones — pure software caps a near-full-scale sustained tone at ~+3 dB, which is insufficient.

## Phase 0 — Measure (host + reasoning; gates the authoring choices)
- Peak level + crest factor of all 14 alert WAVs in `openpilot/selfdrive/assets/sounds/` (confirm the warnings' actual headroom and whether they are steady tones or pulsed).
- Determine the device speaker's efficient frequency band for re-authoring: use any available response data; otherwise a reasoned estimate for small full-range speakers (~2-4 kHz), validated by an on-device sweep in Phase 3.
- Pick a common loudness-normalization target so all re-authored alerts match.

## Phase 1 — Fork substitute WAVs (PRIMARY lever, all devices incl. mici)
Re-author alert tones as fork-added WAVs (new filenames; upstream WAVs never modified). Add with `git add --no-filter` (LFS bypass; format contract stays mono/16-bit/48 kHz). Repoint `sound_list`/`sound_list_sp` at the new files; keep stock paths as fallback.

- **1a (mici must-have): looping safety warnings** (`critical`, `dm_critical`). Re-author as high-RMS waveforms (square/rich) at full scale, at the speaker's efficient frequency, with an attention-grabbing pulsed envelope. This is what clears the mici bar — far beyond the +3 dB software wall.
- **1b (consistency): remaining alerts** normalized to the common loudness target so prompts and warnings match. Done after 1a is validated, so the priority ships first.

Commit a small generator script (extend `make_beeps.py` or use sox/ffmpeg `loudnorm`) so the tones are reproducible and tunable, not hand-edited binaries.

## Phase 2 — Amp register lift (tici/tizi bonus, uniform physical headroom)
- Raise speaker-output volume (`0x3D`/`0x3E`: 23 → ~31) and mixer gain (`0x2D`: 0 → ~3) under the Volume Boost setting; revert to stock values when boost is off. Guard every amp call with `if self.amplifier is not None:` (mici safety). Integrate with the amp init/wake lifecycle.
- Adds physical SPL on top of the electrically-full-scale WAVs. Biggest uniform win on the test device (tizi).

## Phase 3 — Test on tizi (+ mici if available)
- Quiet cabin: confirm alerts are not excessive (ambient gain still scales them down).
- Music cabin: confirm warnings + prompts audible over music; confirm consistency across sounds.
- On-device frequency sweep to validate Phase 0's band estimate; tune WAV frequencies if needed.

## Design notes
- **Single control preserved:** Volume Boost stays the user control (drives the amp gate on tici/tizi). The WAV swap is always-on fork behavior — nothing extra for the user to combine.
- **No runtime DSP maximizer in v1:** the WAVs do the source-level loudness work more controllably. Revisit only if testing shows a gap.
- **Quiet cabin:** the existing ambient-driven gain still scales alert level down in quiet cabins, so baseline loudness stays restrained; safety warnings may be somewhat louder at baseline, which is acceptable for their role.
- **Upstream WAVs are never modified** — only fork-added files are introduced.

## Tools needed
- Bash: Python (scipy) and/or sox/ffmpeg for WAV measurement + authoring; `git add --no-filter` to commit WAVs as real blobs.
