## Defensive zero-guard for Volume Boost

### Context / finding
Claude's review flagged that a `current_volume` of exactly 0 could be amplified by the dB formula (interp term → 0 dB → full scale). Investigation confirmed this is **not a bug today** for two independent reasons:
1. Quiet Mode suppresses by returning `False` from `should_play_sound` → the audio buffer `ret` stays all-zeros → output is silence regardless of volume. It never sets volume to 0.
2. `current_volume` is never 0 anyway (init `0.1`; `calculate_volume` returns `pow(base, x) ∈ [~0.069, 1.0]`; ramp only raises via `max()`).

So this guard is insurance against a future regression (e.g. someone adds a mute-via-volume path). User-approved.

### Change — `openpilot/selfdrive/ui/soundd.py`, `get_sound_data` tail (~2 lines)
Add `and volume > 0` to the boost condition (skip boost when volume is muted/zero → falls through to `out = ret * volume` = silence). This makes the inner `max(volume, 1e-8)` clamp redundant, so simplify `math.log10(max(volume, 1e-8))` → `math.log10(volume)`. No comment (per user).

Before:
```python
    volume = self.current_volume
    if self.alert_volume_boost:
      cv_db = 20.0 * math.log10(max(volume, 1e-8))
      v_frac = self.alert_volume_boost / 100.0
      eff_db = max(cv_db * (1.0 - v_frac), cv_db + v_frac * ALERT_VOLUME_BOOST_DB)
      volume = math.pow(10.0, eff_db / 20.0)
      out = np.clip(ret * volume, -1.0, 1.0)
    else:
      out = ret * volume
    return out
```
After:
```python
    volume = self.current_volume
    if self.alert_volume_boost and volume > 0:
      cv_db = 20.0 * math.log10(volume)
      v_frac = self.alert_volume_boost / 100.0
      eff_db = max(cv_db * (1.0 - v_frac), cv_db + v_frac * ALERT_VOLUME_BOOST_DB)
      volume = math.pow(10.0, eff_db / 20.0)
      out = np.clip(ret * volume, -1.0, 1.0)
    else:
      out = ret * volume
    return out
```
