## Proposed skills

### 1. ui-raylib
**Purpose:** Add or change on-device UI, knowing it is raylib/pyray (not Qt) and uses a
conditional-import fork hook.
**Triggers when:** "UI", "onroad view", "alert renderer", "hud", "widget", "add a UI element",
"settings screen", or when editing anything under `openpilot/selfdrive/ui/`,
`openpilot/system/ui/`, or the `selfdrive/ui/sunnypilot/` fork overlay.
**Priority:** high
**Structure:** SKILL.md body-only
**Content:**
- The UI is **raylib via `pyray`**, wrapped in the `gui_app` singleton
  (`openpilot/system/ui/lib/application.py`). There are no Qt signals/slots anywhere — do not
  reach for them. `gui_app` owns the window/render loop, FPS limiting (tizi caps at 20 fps),
  touch handling, and font/texture loading (`gui_app.texture(...)`, `FontWeight`).
- Widgets render **imperatively** in `_render(rect)` via `rl.draw_*` calls. Layout is a
  parent/push model (`gui_app.push_widget`), not a declarative/QML tree. A new screen or element
  is a `Widget` subclass implementing `_render`.
- The fork hook is a runtime check, `gui_app.sunnypilot_ui()` (set from build/env). When true,
  code does **conditional imports of `*SP` subclasses and multiple inheritance** — e.g.
  `AugmentedRoadView(CameraView, AugmentedRoadViewSP)` in
  `selfdrive/ui/onroad/augmented_road_view.py`, and `AlertRendererSP as AlertRenderer`,
  `HudRendererSP as HudRenderer`, `DriverStateRendererSP as DriverStateRenderer` swap in.
- Fork UI lives under `openpilot/selfdrive/ui/sunnypilot/` mirroring the upstream tree
  (`onroad/`, `layouts/`, `mici/`). **Never edit the upstream UI files to add fork behavior** —
  add a class in the `sunnypilot/` mirror and mix it in or swap the import under the
  `sunnypilot_ui()` check. This mirrors the repo-wide convention of reducing the upstream merge
  surface (see `add-fork-extension`).
- Top-level layout: `selfdrive/ui/layouts/main.py` `MainLayout(Widget)` switches on `MainState`
  (HOME/SETTINGS/ONROAD). Offroad vs onroad is handled by `MainState` and
  `_handle_onroad_transition()`, driven by `ui_state.status` (UIStatus: DISENGAGED/ENGAGED/
  WARNING/ALERT, plus fork `LAT_ONLY`/`LONG_ONLY`).
- Onroad composition: `AugmentedRoadView` composes `alert_renderer`, `hud_renderer`,
  `model_renderer`, `driver_state`. Each is a subscriber with its own `SubMaster` reading cereal
  messages directly — the UI is **pull-based**, not callback-driven.
- Device-specific UI: `selfdrive/ui/mici/` and `selfdrive/ui/sunnypilot/mici/` hold comma-four
  (mici) renderers (e.g. `confidence_ball.py`, a mici-specific `hud_renderer.py`); treat `tici`
  references inside `tizi`/`mici` code paths as supported-but-fragile.
- Reference files: `openpilot/system/ui/lib/application.py`,
  `openpilot/selfdrive/ui/layouts/main.py`,
  `openpilot/selfdrive/ui/onroad/augmented_road_view.py:16-41` (the SP conditional-import +
  multiple-inheritance idiom), `openpilot/selfdrive/ui/sunnypilot/onroad/augmented_road_view.py`,
  `openpilot/selfdrive/ui/sunnypilot/ui_state.py`.

### 2. audio-soundd
**Purpose:** Change alert sounds, loudness, and the soundd audio pipeline in zoompilot/sunnypilot/openpilot.
**Triggers when:** editing `soundd.py`, `micd.py`, alert WAVs / `sound_list`, the
`AudibleAlert`/`AudibleAlertSP` enums, alert volume / loudness / Volume Boost / Quiet Mode, the
MAX98089 amp, adding or replacing a sound, or audio settings.
**Priority:** high
**Structure:** SKILL.md body-only
**Content:**
- **Pipeline map:** `selfdrived` event → `AudibleAlert`/`AudibleAlertSP` enum →
  `selfdriveState.alertSound.raw` → soundd `sound_list` lookup → `get_sound_data` buffer fill →
  `calculate_volume` + Volume Boost → PortAudio output. File:line pointers per stage. soundd runs
  as a managed process gated by `driverview` (onroad + driver-view, NOT offroad).
- **Add/change a sound:** edit `sound_list`/`sound_list_sp` `(filename, play_count, volume)`;
  `play_count=None` loops until stopped at a loop boundary, a number plays N times. WAV MUST be
  mono/16-bit/48 kHz (hard `assert`s in `load_sounds` — wrong format crashes the daemon). Bypass
  LFS with `git add --no-filter <file>` — `*.wav` is LFS-tracked pointing at sunnypilot's GitLab,
  so a plain `git add` becomes an unpushable pointer. `AudibleAlertSP` reserves @9–30 and uses
  @31/@32 (promptSingleLow/High); don't collide with upstream.
- **Loudness model:** no normalization tooling — bake loudness into the WAV PCM. The per-sound
  `volume` field is inert (always `MAX_VOLUME`); runtime level = ambient `calculate_volume`
  (exponential curve, per-device `AMBIENT_DB`/`DB_SCALE`/`VOLUME_BASE`) + Volume Boost (dB-domain
  gain). `current_volume` is FROZEN while an alert plays (mic self-feedback); only
  `warningImmediate` ramps (4 s). Volume Boost: 0% = bit-identical stock; dB-domain `max()` of
  interp-to-full-scale (quiet cabins) and +6 dB additive (loud cabins), hard-clipped; uniform
  perceptual steps at 20% increments; `if boost and volume > 0:` guard never amplifies a muted
  buffer.
- **Device/hardware:** MAX98089 amp on tici/tizi has FIXED registers and NO `set_volume` API —
  all runtime loudness is software PCM scaling in soundd. mici (comma four) has NO amp
  (`HARDWARE.amplifier is None`, all amp calls guarded). tizi differs: `AMBIENT_DB=30`,
  `VOLUME_BASE=10`, and `*_tizi.wav` engage/disengage overrides. Two unrelated sample rates: micd
  input 16 kHz vs soundd output 48 kHz — don't conflate.
- **Settings surface:** audio params (`QuietMode`, `AlertVolumeBoost`, `RecordAudio`) MUST be in
  `params_keys.h` — on prebuilt branches a missing key raises `UnknownKeyName` at runtime, so base
  audio-param work on `develop` (source build). On-device widgets live in `DeviceLayoutSP`
  (`device.py`); mici's `DeviceLayoutMici` has NO audio widgets — add separately. sunnylink:
  `device.yaml` → compiled `settings_ui.json` via `compile_settings_ui.py`; hand-edit JSON
  surgically to avoid the `SmartCruiseDecelOvershoot` landmine (in JSON, no YAML — recompiling
  deletes it).
- **Gotchas:** `import sounddevice` happens after fork (PortAudio is fork-unsafe); volume frozen
  during alerts; looping sounds finish at the loop boundary (no mid-tone cut); no mutex on
  loop/callback shared state (benign — callback only reads). Cross-ref: `add-fork-extension`
  (adding an `AudibleAlertSP` value is a fork extension), `params-store`, `managed-processes`,
  `cereal-messaging`.
